# Frontend тренажёра ЭЛОУ-АВТ

React-интерфейс оператора для существующего backend. Он не вычисляет технологическое
состояние и не содержит скрытых параметров сценария: показания, этапы, тревоги и
статусы команд поступают через WebSocket backend.

## Запуск

Сначала поднимите и заполните backend из [`backend/README.md`](../backend/README.md).
В отдельном терминале:

```bash
cd frontend
npm install
npm run dev
```

Откройте `http://127.0.0.1:5173`. Dev-сервер проксирует `/api` и `/ws` на
`http://127.0.0.1:8000`, поэтому дополнительная CORS-настройка для локальной
разработки не требуется.

Первым экраном будет пульт: обучаемый садится за него без входа. Токена в
хранилище нет — клиент запрашивает гостевой через `POST /auth/guest`, и тот даёт
права ровно на своё прохождение: завести, вести и пройти. Экрана входа обучаемый
не видит вовсе.

Закрыты два раздела, и оба требуют учётной записи:

- **кабинет эксперта** — кнопка на месте, но за ней экран входа: решения по
  сценариям подписываются именем, поэтому анонимно туда не попасть;
- **`/admin`** — рабочее место администратора ИБ на отдельном адресе. С пульта на
  него нет ссылки: на общем компьютере в операторной рабочее место оператора не
  должно вести к журналу доступа даже видом кнопки.

Ссылка «Войти по учётной записи» на стартовом экране нужна инструктору и именному
обучаемому. Учётные записи заводит `uv run python -m app.cli seed-users` на стороне
backend — он же печатает пароли, один раз.

Разграничение делает сервер: скрытый раздел — удобство интерфейса, а не защита.
Открытый напрямую `/admin` без прав покажет тот же экран входа, а запрос к чужому
ресурсу сервер отклонит.

Если приложение раздаётся статикой, нужен SPA-fallback на `index.html` — иначе
`/admin` откроется 404-й страницей веб-сервера. Dev-сервер Vite и `vite preview`
делают это сами.

Кабинет эксперта дополнительно обращается к сервису рекомендаций через прокси `/ml`
на `http://127.0.0.1:8100` (см. [`ml/README.md`](../ml/README.md)). Сервис
необязателен: без него тренажёр работает полностью, а кабинет эксперта показывает,
что рекомендации недоступны.

Для production-сборки:

```bash
npm run build
```

Переменные окружения (полезны, если frontend размещается отдельно):

- `VITE_API_BASE_URL` — REST-префикс, по умолчанию `/api/v1`;
- `VITE_WS_BASE_URL` — origin WebSocket, по умолчанию текущий origin браузера;
- `VITE_ML_BASE_URL` — префикс сервиса рекомендаций, по умолчанию `/ml/v1`.

## Реализованные пользовательские потоки

- самостоятельное прохождение без входа; вход по логину и паролю там, где важно имя;
- экран определяется правами вошедшего, раздел администратора ИБ — адресом `/admin`;
- обучаемый открывает назначенное ему прохождение, инструктор назначает и ведёт;
- выбор опубликованного сценария, уровня сложности и оператора;
- создание, запуск, пауза, продолжение и прерывание сессии;
- WebSocket с восстановлением по `last_sequence_no`;
- пульт с потоковыми показаниями, статусом этапа и тревогами;
- управляющие команды, явные осмотры, диагноз и отмена ещё не применённой команды;
- модальные окна SAGAT и NASA-TLX;
- итоговый отчёт и сравнение пройденных уровней;
- кабинет эксперта: разбор прохождения по навыкам, предлагаемый профильный сценарий,
  очередь предложений с утверждением или отклонением и поиск системных проблем;
- кабинет доступа и аудита: учётные записи, выдача и отзыв ролей, матрица прав
  и журнал событий безопасности.

### Права в интерфейсе

`GET /auth/me` отдаёт список прав, по нему `useAuth().can(...)` прячет недоступные
разделы и кнопки. Это **удобство интерфейса, а не защита**: каждое обращение
проверяет сервер, и спрятанная кнопка ничего не решает — открытый напрямую адрес
получит `403`.

Отсюда же следует, что интерфейс не дублирует матрицу ролей: она читается с сервера
(`GET /roles`) и показывается в кабинете администратора ИБ как есть. Расхождение
между показанным и применяемым было бы хуже отсутствия экрана.

## Структура

```text
src/
├── App.jsx                         # композиция страниц
├── main.jsx                        # точка монтирования React
├── components/
│   ├── Admin/                      # учётные записи, роли и журнал доступа
│   ├── common/                     # переиспользуемые UI-элементы
│   ├── Dashboard/                  # мнемосхема, приборы и управление
│   ├── Forms/                      # форма создания сессии
│   ├── Header/                     # шапка и прогресс этапов
│   ├── Modals/                     # диагноз, SAGAT, NASA-TLX
│   ├── Sessions/                   # список доступных прохождений
│   └── Sidebar/                    # сессия, тревоги, журнал, инструкция
├── constants/                      # статические конфигурации UI
├── hooks/                          # сеанс, состояние тренировки, WS и отчёт
├── pages/                          # вход, старт, пульт, отчёт, эксперт, доступ
├── services/                       # REST, WebSocket и хранение токена
├── styles/                         # глобальный CSS
└── utils/                          # форматирование и сообщения ошибок
```

`useAuth` владеет сеансом: токен лежит в `sessionStorage`, поэтому закрытая вкладка
завершает работу и токен не остаётся на общем компьютере в операторной. Ответ `401`
обнуляет сеанс прямо в слое запросов. Дальше поведение зависит от раздела: на пульте
берётся новый гостевой токен, в закрытых разделах появляется экран входа.

`useRoute` держит адрес страницы: `/admin` — рабочее место администратора ИБ,
всё остальное — пульт. Двух маршрутов достаточно, и роутер ради них не нужен.

`useTrainingSession` является единственным владельцем состояния активной
тренировочной сессии. Локальное состояние форм (например, значения уставок и
ответы SAGAT) остаётся в соответствующих UI-компонентах, поэтому контекст или
глобальный store сейчас не нужны. При появлении нескольких независимых экранов
оператора и инструктора этот хук можно безопасно перевести на `useReducer` или
разделить на несколько context-провайдеров.
